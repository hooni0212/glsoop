# 글숲 Editor 페이지 개편안 v1

## 1. 문서 목적

이 문서는 글숲의 Editor 페이지를 `실사용 가능한 수준`으로 개편하기 위한 제품/UX 기준안을 정리한다.

핵심 목표는 단순하다.

- 사용자가 글을 쓰는 흐름을 해치지 않는다.
- 입력한 글이 처음부터 `읽고 싶게 보이도록` 만든다.
- 사용자가 직접 배치하는 디자인 툴이 아니라, 글의 분위기와 호흡을 자동으로 만들어주는 에디터를 만든다.

이 문서는 기존 Editor 페이지의 장점을 유지하면서, 프리뷰 품질, 페이지 분할, 글 타입별 자동 배치, 실시간 피드백을 강화하는 방향을 전제로 한다.

---

## 2. 제품 정의

### 2.1 Editor의 역할

글숲 Editor는 글을 쓰는 화면이자, 동시에 `책에 인쇄된 느낌의 이미지 카드`를 만들어내는 편집기다.

하지만 그 역할은 일반적인 디자인 툴과 다르다.

- Canva처럼 요소를 자유 배치하는 툴이 아니다.
- 문장과 문단의 성격을 읽고, 가장 읽기 좋은 형태로 정리하는 `분위기 생성기`에 가깝다.

즉, 사용자는 레이아웃을 설계하지 않는다.
사용자는 글을 쓰고, 시스템은 글의 호흡에 맞는 배치와 분할을 제안한다.

### 2.2 Editor의 책임

Editor가 책임지는 영역:

- 가독성
- 여백 설계
- 페이지 분할
- 타이포그래피
- 미리보기 품질
- 피드 업로드용 이미지 카드 생성

작성자가 책임지는 영역:

- 문장력
- 첫 문장의 힘
- 감정의 밀도
- 이야기의 흐름

Editor의 목표는 `글을 대신 잘 쓰게 만드는 것`이 아니라, `잘 쓴 글이 가장 아름답게 보이게 만드는 것`이다.

---

## 3. 개편 방향 한 줄 요약

현재의 좌우 2단 구조는 유지한다.

- 왼쪽: 글 입력과 최소 설정
- 오른쪽: 실제 결과에 가까운 실시간 프리뷰

대신 오른쪽 프리뷰를 단일 카드 미리보기에서 끝내지 않고, `여러 장으로 분할될 수 있는 출판형 프리뷰`로 확장한다.
또한 상단 안내 문구를 단순 설명이 아니라 `품질 피드백 레이어`로 발전시킨다.

---

## 4. 핵심 원칙

### 4.1 자유 배치보다 자동 배치가 우선이다

직접 x/y 좌표를 조정하게 만들수록 사용자는 글쓰기가 아니라 편집 작업을 하게 된다.
글숲 Editor는 사용자가 위치를 만지기 전에, 이미 충분히 좋은 결과를 보여줘야 한다.

원칙:

- 기본값만으로도 예쁘게 보여야 한다.
- 수동 편집은 예외적 보정 수단이어야 한다.
- 레이아웃 결정의 주도권은 시스템이 가진다.

### 4.2 여백이 먼저 보이는 화면이어야 한다

좋은 결과물은 텍스트의 양보다 `여백의 질`이 먼저 보인다.

따라서 Editor는 다음을 우선 판단해야 한다.

- 이 페이지가 빽빽해 보이는가
- 줄 수가 부담스러운가
- 문단 시작이 너무 무거운가
- 제목과 본문이 경쟁하는가
- 여백이 감정을 받쳐주고 있는가

### 4.3 글 타입별로 다른 배치 규칙을 가져야 한다

산문, 운문, 한 구절은 읽는 방식 자체가 다르다.
한 가지 레이아웃 엔진으로 처리하되, 내부 규칙은 타입별로 분리해야 한다.

### 4.4 프리뷰는 결과물이 아니라 판단 도구여야 한다

프리뷰는 "예쁘게 보이는 창"이 아니라, 사용자가 지금 글의 밀도와 호흡을 즉시 판단할 수 있게 해주는 도구여야 한다.

따라서 프리뷰는 다음 정보를 명확히 전달해야 한다.

- 지금 결과물이 한 장인지 여러 장인지
- 어느 페이지가 가장 빽빽한지
- 현재 글이 어떤 모드로 해석되고 있는지
- 조금만 다듬으면 더 좋아질 포인트가 무엇인지

---

## 5. 사용자 목표

Editor를 사용하는 사용자의 실제 목표는 아래에 가깝다.

- 글을 쓰고 싶다.
- 글을 인스타그램/피드에 올렸을 때 읽히는 형태로 만들고 싶다.
- 디자인 툴을 다루지 않고도 결과물이 세련돼 보였으면 좋겠다.
- 글을 쓰는 흐름이 끊기지 않았으면 좋겠다.

즉, 사용자가 원하는 것은 `통제권`보다 `좋은 기본값`이다.

## 6. 페이지 구조 개편안

## 6.1 전체 구조

현재의 2단 구조를 유지한다.

- 좌측 영역: 작성 패널
- 우측 영역: 출판형 프리뷰 패널

데스크톱 기준:

- 좌측 45~50%
- 우측 50~55%

모바일 기준:

- 작성 패널 우선
- 프리뷰 패널은 하단 접이식 또는 탭 전환형

### 6.2 상단 헤더 영역

현재의 설명문은 단순 안내에서 `상태 인지 + 품질 피드백` 역할로 바뀌어야 한다.

구성:

- 페이지 제목: `글쓰기`
- 서브 설명: 짧고 안정적인 문장 1줄
- 현재 해석 모드 배지: `한 구절`, `운문`, `산문`, `자동 감지`
- 품질 피드백 문장 1~2개
- 저장 상태: `저장 중`, `로컬 저장됨`, `마지막 저장 14:32`

예시 카피:

- 여백이 좋아서 편하게 읽혀요.
- 첫 문장이 조금 길어 보여요. 나누면 더 잘 읽힐 수 있어요.
- 운문 형식으로 잘 보이고 있어요.
- 이 글은 3장의 카드로 나뉘어 보여요.

주의:

- 피드백은 평가가 아니라 제안의 톤이어야 한다.
- "부족하다", "문제다" 같은 단어보다 "더 잘 읽힌다", "조금 더 편해진다" 같은 표현을 사용한다.

### 6.3 좌측 작성 패널

좌측은 여전히 `글쓰기 영역`이어야 한다.
설정 항목은 최소화하되, 결과물 품질에 직접 영향을 주는 것만 남긴다.

권장 구성 순서:

1. 제목
2. 본문
3. 글 타입
4. 분위기 프리셋
5. 폰트 스타일
6. 해시태그
7. 저장/발행 액션

현재 구조에서 바꿔야 할 점:

- `글 종류`는 사용자가 직접 고르는 값이 아니라 `자동 감지 + 수동 변경 가능` 구조로 전환
- `폰트`는 단순 폰트 선택이 아니라 `분위기 프리셋`의 하위 요소로 약화
- 레이아웃 편집 토글은 기본 화면에서 전면에 두지 않고, 고급 옵션으로 후순위 배치

### 6.4 우측 프리뷰 패널

우측은 `피드 카드 미리보기`를 넘어 `최종 업로드 결과 프리뷰`에 가까워져야 한다.

구성:

- 프리뷰 헤더
- 페이지 수 표시
- 현재 페이지 인디케이터
- 카드 캐러셀 또는 썸네일 스트립
- 페이지별 밀도 상태
- 고급 보정 진입 버튼

예시:

- 총 3장
- 1 / 3 페이지
- 2페이지가 조금 빽빽해요

중요:

- 사용자는 단일 카드만 보는 것이 아니라, 실제 업로드될 전체 묶음을 봐야 한다.
- 프리뷰에서 `여러 장` 여부가 명확히 드러나야 한다.

## 7. 입력 흐름 개편안

### 7.1 기본 흐름

권장 흐름:

1. 글 입력
2. 시스템이 글 타입을 자동 감지
3. 시스템이 페이지를 자동 분할
4. 시스템이 추천 분위기 프리셋 적용
5. 사용자는 필요 시 글만 다듬거나 모드만 바꾼다
6. 정말 필요한 경우에만 고급 보정 사용

이 흐름에서 사용자의 주 작업은 끝까지 `글 수정`이어야 한다.

### 7.2 글 타입 감지

자동 감지는 필수지만, 강제는 위험하다.

정책:

- 최초 진입 시 `자동 감지`가 기본
- 시스템은 추천 결과를 보여준다
- 사용자는 `산문 / 운문 / 한 구절`로 언제든 바꿀 수 있다
- 수동 변경 시 이후 분할/배치 규칙은 해당 모드 우선

감지 기준 예시:

- 한 구절: 전체 줄 수가 1~4줄이고 총 길이가 짧음
- 운문: 줄바꿈 비율이 높고 평균 줄 길이가 짧음
- 산문: 문단 중심 구조, 줄 길이와 문장 길이가 상대적으로 김

UI 문구 예시:

- 자동 감지: 운문으로 보고 있어요
- 짧은 구절처럼 보여요
- 산문 구조에 더 가까워 보여요

### 7.3 분위기 프리셋

사용자는 좌표를 만지는 대신 `분위기`를 선택한다.

권장 프리셋 방향:

- 고요한 책장
- 따뜻한 종이
- 새벽 메모
- 잔잔한 명조
- 담백한 기록

프리셋이 바꾸는 요소:

- 배경 톤
- 폰트 조합
- 제목/본문 대비
- 여백 밀도
- 정렬 성격
- 장식 요소의 강도

주의:

- 프리셋은 결과의 결을 바꾸되, 구조 자체를 과하게 흔들면 안 된다.
- 글 내용보다 스타일이 앞서 보이면 실패다.

## 8. 모드별 출력 규칙

### 8.1 한 구절 모드

목표:

- 한눈에 임팩트
- 짧은 체류 시간 안에 감정 전달
- 여백이 주인공인 카드

레이아웃 규칙:

- 제목은 기본적으로 생략 가능
- 본문은 1~4줄 권장
- 화면 정중앙보다 약간 위쪽 중심 배치
- 본문 폰트 크기 상대적으로 크게
- 배경과 종이 질감 비중을 더 높게 사용
- 1장 완결을 우선

품질 규칙:

- 문장이 길어지면 자동으로 글자 크기를 줄이기보다 2장 분할을 먼저 검토
- 제목이 본문과 경쟁하면 제목은 숨김 추천

### 8.2 운문 모드

목표:

- 줄바꿈의 리듬 유지
- 연과 연 사이 호흡 유지
- 시가 조용히 놓여 있는 느낌

레이아웃 규칙:

- 좌측 정렬 기본
- 한 줄 최대 길이를 짧게 유지
- 행간을 산문보다 넓게
- 연 간격을 명확히 구분
- 페이지당 줄 수 강한 제한

분할 규칙:

- 연 단위를 가급적 쪼개지 않는다
- 한 페이지 마지막 줄에 고립된 한 행만 남지 않게 한다
- 다음 페이지 첫 화면이 지나치게 빈약하지 않도록 균형 조정

### 8.3 산문 모드

목표:

- 긴 글도 부담 없이 넘겨 읽히게 만들기
- 문단 단위로 호흡을 나누기
- 마지막 장에 여운 남기기

레이아웃 규칙:

- 제목은 상단에 짧고 선명하게
- 본문은 제목보다 한 단계 아래에 안정적으로 배치
- 첫 문단 시작이 너무 무겁지 않도록 상단 여백 확보
- 한 페이지에 모든 글을 억지로 넣지 않음

분할 규칙:

- 문단 단위 우선 분할
- 첫 페이지 과밀 금지
- 마지막 페이지는 다소 짧아도 허용
- 페이지별 글자 수 균등보다 `읽는 호흡` 우선

## 9. 페이지 분할 엔진 규칙

실사용 수준으로 가기 위해서는 페이지 분할 규칙이 문서로 명확해야 한다.

우선순위는 아래와 같다.

1. 가독성
2. 여백 확보
3. 글의 의미 단위 유지
4. 페이지 간 균형

### 9.1 공통 분할 기준

- 페이지별 최대 텍스트 밀도를 넘기지 않는다
- 제목, 본문, 메타가 서로 경쟁하지 않게 한다
- 첫 페이지는 진입 장벽이 낮아야 한다
- 마지막 페이지는 여운을 허용한다

### 9.2 분할 금지 규칙

- 문단 중간을 부자연스럽게 자르지 않는다
- 운문에서 한 연의 핵심 행을 분리하지 않는다
- 너무 짧은 마지막 페이지를 만들기 위해 앞 페이지를 과밀하게 만들지 않는다

### 9.3 분할 후 보정

자동 분할 후 시스템은 다음을 재검토한다.

- 특정 페이지만 유난히 빽빽한가
- 특정 페이지의 여백이 지나치게 넓은가
- 첫 페이지가 너무 무거운가
- 마지막 페이지가 지나치게 허전한가

필요 시:

- 문단 재배치
- 줄바꿈 재계산
- 글자 크기 소폭 보정
- 페이지 수 증감 제안

## 10. 실시간 프리뷰 설계

### 10.1 프리뷰 원칙

- 입력 즉시 반응해야 한다
- 단순 텍스트 미러링이 아니라 실제 카드 결과에 최대한 가까워야 한다
- 페이지 분할 결과가 즉시 보여야 한다
- 사용자가 어느 수정이 결과에 영향을 주는지 바로 이해할 수 있어야 한다

### 10.2 프리뷰 구조

프리뷰 패널은 아래 계층으로 구성된다.

- 대표 프리뷰 카드
- 페이지 썸네일 목록
- 페이지 정보 바
- 품질 피드백

예시 정보 바:

- 자동 감지: 산문
- 총 4장
- 현재 2페이지
- 이 페이지는 본문 밀도가 조금 높아요

### 10.3 인터랙션

- 입력 중에는 부드럽게 실시간 반영
- 분할 수가 바뀌면 페이지 수 변화 애니메이션 표시
- 현재 수정된 페이지를 우선 보여주되, 전체 썸네일도 함께 유지
- 모바일에서는 대표 페이지 우선, 전체 목록은 하단 스와이프

---

## 11. 품질 피드백 시스템

상단 안내 영역은 향후 Editor의 핵심 가치가 될 수 있다.

이 영역은 사용자를 평가하지 않고, 글이 더 읽히게 만드는 방향을 조용히 안내해야 한다.

### 11.1 피드백 범주

- 밀도 피드백
- 첫 문장 피드백
- 여백 피드백
- 분할 피드백
- 모드 적합성 피드백

### 11.2 예시 문구

- 이 페이지는 조금 빽빽해 보여요. 문단을 한 번 나누면 더 편하게 읽혀요.
- 지금은 짧은 구절 형태로 아주 잘 보이고 있어요.
- 마지막 페이지의 여백이 좋아서 여운이 남아요.
- 운문으로 바꾸면 줄바꿈의 느낌이 더 잘 살아날 수 있어요.
- 제목이 본문보다 조금 강하게 보여요. 제목 톤을 낮추면 더 안정적이에요.

### 11.3 사용 원칙

- 한 번에 1~2개만 노출
- 긍정 피드백을 함께 제공
- 반복 문구를 피하고, 같은 유형 피드백은 빈도 제한

## 12. 고급 보정 기능의 위치

고급 보정은 필요하지만, 메인 경험을 지배하면 안 된다.

현재 `레이아웃 편집 ON` 중심 구조는 실험 기능으로는 의미가 있지만, 기본 사용자 경험의 전면에 나와 있으면 제품의 정체성이 흐려진다.

정리 방향:

- 기본 모드에서는 자동 배치만 노출
- 고급 보정은 `세부 조정` 또는 `고급 편집`으로 접어둔다
- 수동 조정이 필요한 경우에만 진입

고급 보정에서 허용할 항목:

- 제목 숨김
- 제목/본문 비율 미세 조정
- 페이지별 정렬 변경
- 글자 크기 소폭 조정
- 안전 영역 경고 확인

가급적 숨길 항목:

- 자유 드래그
- 박스 리사이즈
- 좌표 단위 수동 배치

실무적 판단:

완전히 제거할 필요는 없지만, `주력 기능`이 아니라 `예외 기능`으로 내려야 한다.

## 13. 저장과 초안 경험

실사용 수준에서 중요한 것은 결과물의 미감만이 아니다.
사용자는 자주 멈췄다가 다시 쓰고, 수정하고, 저장 상태를 불안해한다.

필수 경험:

- 자동 저장
- 저장 시각 표시
- 로컬 초안 복구
- 편집 중 이탈 보호

표현 원칙:

- 저장 상태는 조용하지만 분명해야 한다
- 오류는 즉시 보이되 과하게 불안을 주지 않아야 한다
- 초안 복구는 강요가 아니라 선택이어야 한다

예시 문구:

- 방금 저장되었어요
- 기기에 임시 저장했어요
- 네트워크가 불안정해요. 연결되면 다시 저장할게요

---

## 14. Post 페이지와의 연결

Editor 개편은 Post 페이지 개편과 분리될 수 없다.
Editor에서 여러 장으로 보이는 구조라면, 읽기 화면에서도 그 구조가 자연스럽게 이어져야 한다.

정리해야 할 항목:

- 여러 장 업로드 시 Post 페이지 표시 방식
- 대표 이미지 선택 규칙
- 썸네일/페이지 인디케이터 여부
- 공유 시 첫 장만 보여줄지, 캐러셀임을 명시할지

원칙:

- Editor에서 본 결과와 Post에서 본 결과가 크게 다르면 안 된다
- 작성자와 독자가 보는 리듬이 최대한 일치해야 한다

## 15. 모바일 기준

모바일은 별도 우선순위가 필요하다.

핵심:

- 글쓰기 흐름 방해 최소화
- 프리뷰 접근성 확보
- 페이지 수 인지 명확화

권장 구조:

- 상단: 제목 + 저장 상태
- 본문 입력
- 하단 고정 바: `프리뷰 보기`, `모드`, `저장`
- 프리뷰는 전체 화면 슬라이드 업 또는 탭 전환

모바일에서 피해야 할 것:

- 본문 입력 중 항상 큰 프리뷰 노출
- 작은 화면에서 복잡한 레이아웃 보정 UI 제공
- 다수의 드래그 핸들 노출

---

## 16. 성공 기준

개편의 성공은 기능 추가 수가 아니라 아래 지표로 판단해야 한다.

- 사용자가 저장 전까지 머무는 시간 증가
- 초안 저장 후 재진입률 증가
- 다장 카드 사용 비율 증가
- 저장 후 즉시 이탈 감소
- 게시 후 열람/완독 관련 지표 개선
- 사용자 주관 평가에서 "예쁘게 나온다", "읽기 편하다" 응답 증가

정성 기준:

- 사용자가 배치를 만지지 않아도 만족감을 느낀다
- 글을 적는 동안 디자인 툴에 들어온 느낌이 나지 않는다
- 프리뷰를 보고 글 자체를 다듬고 싶어진다

## 17. 최종 제안

글숲 Editor는 `글쓰기 화면`의 감각을 유지한 채, `출판형 프리뷰`와 `자동 배치 로직`을 강화하는 방향으로 개편하는 것이 맞다.

핵심 제안은 아래 세 가지다.

1. 현재의 좌우 2단 레이아웃은 유지한다.
2. 레이아웃 편집 중심 경험을 자동 분할/자동 배치 중심 경험으로 재정렬한다.
3. 상단 안내와 우측 프리뷰를 품질 피드백 중심으로 고도화한다.

한 문장으로 정리하면:

`글숲 Editor는 사용자가 디자인하지 않아도, 글이 처음부터 읽고 싶게 보이게 만드는 에디터`가 되어야 한다.

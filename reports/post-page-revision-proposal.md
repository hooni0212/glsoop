# 글숲 Post 페이지 개편안 v1

## 1. 문서 목적

이 문서는 글숲의 Post 페이지를 Editor 개편 방향과 연결된 읽기 화면으로 재정의하기 위한 개편안이다.

핵심 전제는 분명하다.

- Editor가 `책에 인쇄된 느낌의 이미지 카드`를 만든다면
- Post는 그 결과물을 `가장 자연스럽게 읽고 감상하는 화면`이 되어야 한다.

즉, Post 페이지는 단순 상세 페이지가 아니라, 글숲의 출력 모델을 완성하는 읽기 인터페이스여야 한다.

---

## 2. 왜 Post 개편이 함께 필요한가

Editor가 자동 분할, 다장 카드, 여백 중심 레이아웃으로 발전하면, Post 페이지도 같은 리듬을 받아야 한다.

그렇지 않으면 다음 문제가 생긴다.

- Editor에서는 여러 장으로 보였는데 Post에서는 한 장처럼 소비된다.
- 작성자가 본 결과와 독자가 읽는 경험이 달라진다.
- 여백과 호흡 중심으로 설계된 카드가 상세 페이지에서 평범한 본문처럼 느껴진다.
- 다장 글의 흐름이 끊기고, 캐러셀 구조의 의미가 사라진다.

따라서 Editor와 Post는 별개 화면이 아니라, 하나의 출력 체계를 공유해야 한다.

---

## 3. Post 페이지의 역할 재정의

### 3.1 기존 역할

현재 Post 페이지는 `글 상세 보기`, `좋아요/북마크/공유`, `관련 글 탐색` 중심의 상세 페이지다.

이 구조는 기본적으로 맞다.
다만 앞으로는 그 위에 아래 역할이 더해져야 한다.

### 3.2 새 역할

Post 페이지는 다음 네 가지 역할을 동시에 수행해야 한다.

- 읽기
- 감상
- 넘김
- 이어 읽기

즉, 단순히 텍스트를 보여주는 것이 아니라,
`카드로 구성된 글을 한 장씩 읽는 경험`과 `글 전체를 하나의 작품처럼 감상하는 경험`을 함께 제공해야 한다.

---

## 4. 개편 방향 한 줄 요약

Post 페이지는 `상세 본문 레이아웃`에서 `출판형 읽기 레이아웃`으로 이동해야 한다.

하지만 중요한 것은 과한 연출이 아니다.

- 글보다 UI가 앞서면 안 된다.
- 읽기 흐름보다 기능이 먼저 보이면 안 된다.
- 다장 구조를 보여주되, 조작감은 조용하고 직관적이어야 한다.

한 문장으로 정리하면:

`작성자가 만든 카드의 호흡을 독자가 가장 편안하게 따라가게 만드는 화면`이 Post 페이지의 목표다.

---

## 5. 핵심 원칙

### 5.1 Editor와 Post는 같은 결과물을 봐야 한다

작성자가 Editor에서 본 페이지 수, 카드 순서, 여백의 리듬이 Post에서도 최대한 유지되어야 한다.

원칙:

- 페이지 수를 그대로 반영한다.
- 대표 카드만 보여주는 구조로 축소하지 않는다.
- 카드 간 순서를 유지한다.
- 카드별 밀도 차이와 여백 감각을 보존한다.

### 5.2 읽기 화면은 조용해야 한다

글숲의 Post 페이지는 일반 SNS 상세 페이지보다 더 `정적인 감상`에 맞아야 한다.

따라서:

- 액션 버튼이 본문보다 먼저 들어오면 안 된다.
- 관련 글이 너무 빨리 시선을 가져가면 안 된다.
- 상단 안내 카피는 분위기를 보조하되 과장되면 안 된다.

### 5.3 다장 글은 '넘겨 읽는 경험'이 명확해야 한다

특히 산문과 운문은 여러 장으로 나뉘는 경우가 많기 때문에, 독자는 지금 몇 장째 읽고 있는지 자연스럽게 인식해야 한다.

필수 요소:

- 전체 페이지 수
- 현재 페이지 위치
- 좌우 넘김 또는 세로 이어 읽기 중 현재 방식의 명확한 표시

### 5.4 메타 정보는 감상 이후에 들어와야 한다

카테고리, 해시태그, 관련 글, 작성 시각, 액션 영역은 중요하지만, 본문보다 먼저 화면을 점유하면 안 된다.

Post 페이지의 위계는 아래가 되어야 한다.

1. 글
2. 페이지 흐름
3. 작성자/메타
4. 액션
5. 관련 글

---

## 6. 사용자 목표

Post 페이지를 찾는 독자의 실제 목표는 다음에 가깝다.

- 글을 편하게 읽고 싶다.
- 이미지 카드가 왜 예쁜지 자연스럽게 느끼고 싶다.
- 길다면 부담 없이 넘겨 읽고 싶다.
- 마음에 들면 저장하거나 공유하고 싶다.
- 비슷한 글로 자연스럽게 이어지고 싶다.

즉, Post 페이지는 읽기를 막지 않는 선에서 행동을 유도해야 한다.

---

## 7. 정보 구조 개편안

## 7.1 전체 구조

현재의 `본문 + 우측 보조 패널` 구조는 유지 가능하다.
다만 본문 영역 안의 우선순위를 다시 정리해야 한다.

권장 구조:

- 상단 읽기 인트로
- 메인 읽기 스테이지
- 페이지 네비게이션
- 글 메타 영역
- 액션 영역
- 관련 글

데스크톱:

- 메인 읽기 스테이지 중심
- 우측 패널은 보조 역할 유지

모바일:

- 읽기 스테이지 단일 컬럼 우선
- 액션은 하단 고정 또는 하단 접이식
- 관련 글은 본문 완독 후 배치

### 7.2 상단 읽기 인트로

현재의 `READING MODE / 오늘의 글 / 긴 호흡으로 읽어보세요` 구조는 방향이 나쁘지 않다.
다만 앞으로는 카드형 읽기 경험을 더 정확히 설명해야 한다.

포함 요소:

- 글 타입 배지
- 전체 페이지 수
- 읽기 모드 설명 1줄
- 작성자 정보
- 발행 시각

예시:

- 산문
- 총 4장
- 문단의 호흡에 맞춰 나뉜 글이에요
- 2026.03.19 게시

인트로 카피는 감성적이어도 되지만, 기능적 정보가 함께 보여야 한다.

### 7.3 메인 읽기 스테이지

이 영역이 Post 개편의 중심이다.

핵심은 `다장 카드 묶음을 하나의 글처럼 읽는 구조`를 만드는 것이다.

권장 구조:

- 중앙에 현재 읽는 카드 1장 크게 노출
- 양옆 또는 하단에 이전/다음 카드 암시
- 카드 아래에 페이지 인디케이터 표시
- 확대 없이도 충분히 읽히는 기본 크기 유지

선택 가능한 읽기 방식:

- 기본: 한 장씩 넘기는 카드 뷰
- 보조: 전체를 세로로 이어 읽는 리니어 뷰

실서비스 기준 권장:

- 기본값은 카드 뷰
- `한 번에 이어 읽기` 토글을 보조 기능으로 제공

이유:

- Editor가 만든 여백과 페이지 호흡을 가장 잘 살리는 방식이 카드 뷰이기 때문이다.

---

## 8. 읽기 모드 설계

### 8.1 기본 모드: 카드 읽기

독자는 한 장씩 넘기며 글을 읽는다.

장점:

- 페이지 호흡이 살아난다
- 여백의 감상이 가능하다
- 한 구절/운문/산문 모두 같은 출력 모델 안에서 통일된다

구성:

- 이전 / 다음 버튼
- 스와이프 지원
- 키보드 좌우키 지원
- `1 / 4` 형태의 페이지 표시

UI 원칙:

- 버튼은 조용하게
- 카드보다 컨트롤이 튀지 않게
- 현재 장에 집중이 깨지지 않게

### 8.2 보조 모드: 이어 읽기

긴 산문 사용자나 빠르게 훑고 싶은 독자를 위해 카드 전체를 세로로 이어 보는 모드도 의미가 있다.

적합한 경우:

- 산문 카드 수가 많은 경우
- 독자가 맥락을 빠르게 파악하고 싶은 경우

구성:

- 모든 카드가 세로로 이어짐
- 카드 간 충분한 간격 유지
- 현재 읽고 있는 장 하이라이트 가능

주의:

- 기본 모드가 되어서는 안 된다
- 카드 분할의 의미를 없애는 화면이 되면 안 된다

### 8.3 모드 전환 원칙

- 모드 전환은 옵션이지 의무가 아니다
- 기본 모드를 건드리지 않는 위치에 둔다
- `카드로 읽기 / 이어 읽기` 정도의 명확한 네이밍 사용

---

## 9. 글 타입별 읽기 경험

### 9.1 한 구절

목표:

- 한 장에서 정서적 임팩트 전달
- 감상 시간이 짧아도 밀도 있게 남기기

읽기 구조:

- 대부분 1장 완결
- 카드 단독 감상에 집중
- 메타 정보는 카드 아래로 충분히 내림

특징:

- 카드 주변 여백이 중요
- 액션 버튼보다 카드 자체가 먼저 보여야 함

### 9.2 운문

목표:

- 줄바꿈 리듬 유지
- 연의 흐름을 끊지 않기

읽기 구조:

- 카드 간 넘김이 자연스러워야 함
- 현재 읽는 장과 다음 장의 관계가 부드럽게 이어져야 함

권장 보조 기능:

- 연 단위 분할 설명
- 페이지 전환 시 미세한 페이드 전환

### 9.3 산문

목표:

- 긴 글도 부담 없이 읽히게 만들기
- "계속 읽을 수 있겠다"는 감각 유지

읽기 구조:

- 첫 장 진입 장벽이 낮아야 함
- 중간 장에서는 흐름을 잃지 않게 해야 함
- 마지막 장은 여운을 남기게 해야 함

보조 정보:

- `총 5장 중 2장째` 같은 진행 인지
- 예상 읽기 시간
- 이어 읽기 모드 보조 제공

---

## 10. 페이지 네비게이션 개편안

다장 글이 늘어날수록 페이지 네비게이션은 핵심 경험이 된다.

필수 구성:

- 현재 페이지 번호
- 총 페이지 수
- 이전/다음 이동
- 썸네일 또는 미니 인디케이터

권장 구조:

- 카드 아래 중앙: `2 / 5`
- 좌우 양끝: 이전/다음
- 하단: 작은 썸네일 스트립 또는 점 인디케이터

운영 원칙:

- 1장 글에는 과한 네비게이션을 숨긴다
- 2~3장 정도는 점 인디케이터만으로 충분
- 4장 이상부터는 썸네일/장 목록이 유용

예시:

- 1장: 페이지 UI 최소화
- 2~3장: 숫자 + 점
- 4장 이상: 숫자 + 점 + 썸네일

---

## 11. 메타 정보 배치

메타 정보는 글을 다 읽은 뒤 자연스럽게 보이는 위치로 내려야 한다.

권장 순서:

1. 작성자
2. 카테고리
3. 해시태그
4. 발행 시각
5. 읽기 시간 또는 페이지 수

현재 구조의 보완점:

- 카테고리/태그 바가 본문과 분리되어 있는 점은 좋다
- 다만 앞으로는 `페이지 수`, `글 타입`, `읽기 방식`도 같은 정보 체계 안에 들어와야 한다

예시:

- 산문
- 총 4장
- 2분 읽기
- #밤산책 #새벽기록

---

## 12. 액션 영역 개편안

좋아요, 북마크, 공유는 유지하되, 읽기 흐름을 방해하지 않게 재배치해야 한다.

원칙:

- 카드 상단이나 본문 내부에 섞지 않는다
- 읽기 도중보다 읽은 뒤 반응하도록 유도한다
- 모바일에서는 하단 고정 액션이 유효하되 과하지 않아야 한다

권장 위치:

- 데스크톱: 우측 보조 패널 유지
- 모바일: 하단 반고정 액션 바

추가 고려:

- 다 읽은 시점에 공유 CTA 강화
- 북마크는 조용하게 유지
- 좋아요 수보다 반응 자체를 쉽게 만드는 쪽이 중요

예시 카피:

- 이 글을 저장해두고 다시 읽어보세요
- 마음에 남았다면 공유해보세요

---

## 13. 관련 글 영역 개편안

관련 글은 중요하지만, 본문을 읽기 전에 시선을 빼앗으면 안 된다.

따라서 관련 글은 `보조 탐색`이어야 한다.

원칙:

- 본문 완독 이후의 자연스러운 다음 행동이어야 한다
- 현재 글과 리듬이 비슷한 글을 우선 추천한다
- 단순 최신글보다 `같은 감정/유형/길이`를 고려한다

추천 기준 예시:

- 같은 글 타입
- 비슷한 카드 수
- 유사한 태그
- 같은 분위기 프리셋

UI 방향:

- 현재의 하이라이트 1개 + 리스트 구조는 유지 가능
- 다만 제목 중심보다 `카드 톤`이 보이는 썸네일이 더 중요해질 수 있다

---

## 14. Editor와 Post의 연결 규칙

이 항목은 가장 중요하다.

Editor에서 정해진 결과가 Post에서 어떻게 이어지는지 명확해야 한다.

공유해야 하는 항목:

- 글 타입
- 페이지 수
- 카드 순서
- 프리셋 정보
- 제목 노출 여부
- 페이지별 이미지
- 페이지별 텍스트 분할

반드시 일치해야 하는 것:

- 카드 장수
- 카드 순서
- 제목/본문의 기본 위계
- 대표 장의 선택 기준

허용 가능한 차이:

- Post에서는 카드 크기가 더 커질 수 있음
- 읽기 도구와 메타 정보는 추가될 수 있음
- 이어 읽기 모드처럼 보조 뷰는 추가될 수 있음

허용되지 않는 차이:

- Editor에서 3장인데 Post에서 1장처럼 소비됨
- 제목이 Editor에서는 숨김인데 Post에서 다시 강하게 노출됨
- 카드 순서나 분할 위치가 달라짐

---

## 15. 모바일 기준

모바일에서는 Post 페이지가 사실상 핵심 읽기 화면이 된다.

그래서 더 단순하고 명확해야 한다.

핵심 원칙:

- 현재 장에 집중
- 넘김이 쉬움
- 액션은 뒤로

권장 구조:

- 상단: 작성자 + 글 타입 + 페이지 수
- 중앙: 카드
- 카드 아래: `이전 / 2 / 5 / 다음`
- 하단: 좋아요 / 북마크 / 공유
- 관련 글: 본문 종료 후 노출

모바일에서 중요한 점:

- 스와이프가 자연스러워야 함
- 카드가 화면에 꽉 차되 답답하지 않아야 함
- 첫 화면에서 메타 정보가 카드보다 커 보이면 안 됨

---

## 16. 상태별 UX

### 16.1 1장 글

- 네비게이션 최소화
- 카드 감상 중심
- 메타/액션은 단순하게

### 16.2 2~3장 글

- 카드 넘김 중심
- 점 인디케이터 정도면 충분
- 진행감이 부담 없이 느껴져야 함

### 16.3 4장 이상 글

- 현재 위치 인지가 중요
- 썸네일 또는 장 목록이 유용
- 이어 읽기 모드의 가치가 커짐

### 16.4 렌더 이미지 없음

이미지 카드가 없고 텍스트 기반 렌더만 가능한 경우도 고려해야 한다.

원칙:

- Post는 항상 읽을 수 있어야 한다
- 비주얼 품질이 낮아져도 구조는 유지해야 한다
- fallback에서도 페이지 분할 개념은 유지한다

## 17. 성공 기준

Post 개편의 성공은 단순 체류 시간만으로 보지 않는다.

핵심 지표:

- 다장 글 완독률 상승
- 다음 페이지 이동률 상승
- 공유 전환율 상승
- 북마크 전환율 상승
- 관련 글 클릭률의 질 개선

정성 지표:

- "읽기 편하다"
- "사진첩처럼 넘겨 읽는 느낌이 좋다"
- "글이 작품처럼 보인다"
- "긴 글도 부담이 덜하다"

## 18. 최종 제안

Post 페이지는 앞으로 `상세 보기 화면`이 아니라 `출판형 읽기 화면`이 되어야 한다.

핵심 제안은 아래와 같다.

1. Editor의 다장 카드 구조를 Post에서 그대로 읽을 수 있게 만든다.
2. 읽기 중심 위계를 유지하고, 메타/액션/관련 글은 후순위로 재배치한다.
3. 기본 읽기 모드는 카드 넘김, 보조 읽기 모드는 이어 읽기로 설계한다.

한 문장으로 요약하면:

`글숲 Post는 카드로 만들어진 글을 가장 조용하고 아름답게 읽게 해주는 화면`이어야 한다.
